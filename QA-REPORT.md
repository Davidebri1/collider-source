**Build tested:** `source/` @ Flutter 3.47.2 / Dart 3.13.2

---

## Summary

No crashes, no uncaught exceptions, no console errors, no failed network
requests across every surface walked. The app boots clean, all 8 surfaces open
and close, and the browser request log is 100% HTTP 200.

Every defect found is a **presentation / data-quality** defect, not a stability
one. The dominant theme: the runtime catalog is generated from Drive filenames,
so machine identifiers were leaking straight into user-facing UI in three
separate places. Those are fixed.

## Fixed

### [P1] Raw asset filenames shown as theme titles

* **Where:** Theme Gallery, Premium Market, Discover Market hero, Files library
* **Root cause:** the app loads the hosted catalog from
  `https://davidebri1.github.io/collider-media/themes.json`, generated by
  `collider-drive-sync`. Drive imports are named after their source file, so
  `name` arrives as `0251d1e0-16a1-49ad-9807-19d1bceac3e9_1080_hd`,
  `5899755_Landscape_Lake_1920×1080`, `0_Cat_Rain_1280x720`.
  `WallpaperTheme.fromJson` passed it straight through.
* **Fix:** `humanizeThemeName()` in `lib/models/theme_def.dart` — detects
  filename-shaped titles (underscores, resolution tokens, UUID/hex prefixes,
  long digit runs, file extensions, long hyphen slugs) and rewrites them
  (strip resolution / copy marker / extension / UUID, title-case, drop
  all-numeric remnants → `Untitled Theme`). Curated names such as
  `Tide Concrete`, `VisionOS Spatial Room`, `Canopy Shafts` are detected as
  clean and left byte-for-byte untouched.
* **Result:** `0_Cat_Rain_1280x720` → `Cat Rain`;
  `Artist_desk_at_night_202606151527` → `Artist Desk at Night`;
  bare UUID → `Untitled Theme`.

### [P2] Every song row printed its title twice

* **Where:** Files → library list, Files → Music tab, music drawer
* **Root cause:** `MusicPlayer.themeTracks()` passed `subtitle: theme.name`.
  The generated catalog sets a pack song's `title` to the same value as the
  theme `name`, so every row rendered an identical string on both lines.
  Confirmed in the a11y tree: `"0251d1e0-…_1080_hd 0251d1e0-…_1080_hd Play"`.
* **Fix:** subtitle only carries the theme name when the song has its own.

### [P2] Premium Market: ~144px void under the Apply button

* **Where:** `PremiumThemeMarketView`
* **Root cause:** `_kLabelsBlockHeight` unconditionally reserves
  `_kSongsBlockHeight` (3 × 44px) for a song carousel. Most catalog entries
  ship no tracks, so the top-aligned column ended under the name while the
  reserved rows stayed empty — content stranded high with a large void below.
* **Fix:** `_kLabelsBlockHeightFor(hasSongs)` reserves the carousel only when
  the focused pack actually has tracks. Vertical centring uses the real height.

### [P2] Discover Market grid repeated the same clip 4×

* **Where:** `MarketScreen._seed()`
* **Root cause:** the catalog holds one entry per uploaded file, so the same
  clip appears under ids differing only by a trailing Drive hash. One family
  had four: `…coastline-ocean-1280x720-utox9s`, `…-1280x720-tze-ww`,
  `…-1920x1080-zdumii`, `…-3840x2160-qquj8o`. Deduping on the raw id let all
  four render. A 3-way family (`0-reflection-lake-…`) and a 2-way family
  (`observatory-…` still + loop) had the same shape.
* **Fix:** dedupe on `stemFor(id)` — normalised, with the resolution token and
  the trailing Drive segment(s) peeled off. Verified against the live catalog:
  the coastline family now contributes exactly one tile.
* **Note:** some tiles still *look* alike — Hyper Transit and Deep Ocean Still
  are both teal, Ocean Reflection and Coastline are both warm sunsets. Those are
  genuinely distinct entries that share a palette, not a dedupe miss.

### [P3] Every icon button announced its label twice

* **Where:** `VCircleButton` — side rail, dock, all close buttons
* **Root cause:** `Semantics(button: true, label: tooltip)` wrapped a `VPress`
  that also renders `Tooltip(message: tooltip)`. The tooltip publishes its own
  semantic node, so screen readers read the name twice
  (`"New Chat New Chat"`, `"Apps Apps"`).
* **Fix:** `excludeFromSemantics: true` on the `Tooltip`; the explicit
  `Semantics` label remains. Fixes every circle button in the app at once.

### [P3] Dead code removed

`_chatTab` + the `SideNavTab` enum, `_newConversation`, `_marketSearchQuery`
and its `onMarketSearch` plumbing, `_marketSearchCtrl`, `_toggleControl`, and
the `activePills` alias. All verified unreferenced before removal.

## Reported, not fixed

### [P2] Apps pane and Settings popover have no scrim — labels illegible

Both float directly over a bright live wallpaper with no dim/blur behind them.
White labels ("Smart Gen", "Market", "Account", "Incognito") land on near-white
sky and fail contrast. Every other overlay in the app goes through `VScrim`
(0.35 + medium blur per the code comments); these two do not. The Apps pane's
close button also floats detached at the top-right, far from the icon cluster.

### [P2] Files window is near-full-bleed

The Files panel spans ~8px insets on the left and right — effectively
edge-to-edge. Every other surface floats with real margins.

### [P3] Browser iframe not clipped to the panel radius

The web view's white page overhangs the rounded bottom-right corner of its
frame by a few pixels.

### [P3] Doubled labels remain on some rows

`FilesScreen` rows and the Settings popover still announce
`"Recently Added Recently Added"`. Same class of issue as the `VCircleButton`
fix but in `FText`/`FGlass` rows rather than the kit button; left alone to keep
the change set reviewable.

### [P3] Unreachable Market/Smart Gen/Files rail entries

`SideNavRail` still defines `search/prompts/visuals/video/audio/gallery` for the
Market surface, but `_railVisible` only allows the rail on Home and Themes, so
those entries can never be shown. Dead but harmless.

## What's working well

- Zero crashes and zero console errors across the whole walk.
- Every network request returned 200; the remote catalog, posters, stills and
  fonts all load.
- All 8 surfaces (Apps, Smart Gen, Market, Themes, Premium, Files, Browser,
  Settings) open and close correctly, and state survives surface switches.
- Backdrop blur / glass stacking renders correctly on web.
- Touch targets are consistently sized and comfortably above the 44px floor.
- Panel geometry holds at 430×932; no overflow stripes or RenderFlex errors.

## Recommendations

1. **Fix the catalog generator, not just the client.** `collider-drive-sync`
   should write curated `name` values at generation time. The client-side
   humanizer is the right safety net, but it cannot invent a good name for a
   file Drive never had one for.
2. Add a scrim behind the Apps pane and Settings popover.
3. Add `Widget`/`integration_test` smoke coverage: boot → open each of the 8
   surfaces → assert no exception. That would have caught the double-label
   regression class cheaply.
4. Consider the files window's margins.
